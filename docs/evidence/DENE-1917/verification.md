# DENE-1917 验证与交付边界

按 Kun 最终确认规格：派活、咨询、验收共用 `routeTicket(ticket, purpose)`。咨询与验收目标为执行人的高一档；验收只禁止执行人自审，顾问可以验收。类别系列是排序权重；目标档全部系列不可用后，尝试上、下相邻档。最强档不能作为替补，明确目标仍须额度宽裕。不配置项目兜底名单。

## DENE-1916 根因

基线 d5f8732f22 包含 #659/#660 对应改动。原票路由评论同时出现系列偏好与“额度紧张，但没有别的可用席位，只能派她”，说明相关逻辑被执行，不能简单归因为服务没升级。

旧系列过滤只要任意档有 Claude 就保留 Claude 池；布尔玛仍在最强档，导致中档特兰克斯被排除。后续最强档门槛在已过滤的池中看不到特兰克斯，且保留了额度紧张时仍派最强档的出口。新实现消除这两处条件漏洞。现有 CLI 和记录不能确认事故时精确部署 SHA；未声称已核实服务器版本。

同样输入（中档前端、天津饭 mention_only、布尔玛额度紧张、特兰克斯可用）：基线回归失败并选布尔玛；修改后通过并选特兰克斯；独立副本回滚后再现原失败。回滚副本哈希恢复原值；补丁可重建整个修改模块。

## 范围与风险

一个推理调用输出档位、席位、原因、置信度；低置信度最多升一档，不能因此升到最强。原有工作区保留 legacy 迁移状态；shadow/active 不调用独立 judge。设置高级区提供历史比较和启用入口，CLI 同一服务端接口提供 `workspace routing shadow --days 30`。

未修改线上设置、未部署。线上当前缺少新增影子 API，因此真实近 30 天全量对照尚未执行；本地没有生产推理端点，未把模拟推理结果记成真实模型调用。应在部署后先做影子对照，再切 active。此项交 Grok 在审查和上线流程中判断，不能把本 PR 合并当作已经切换。

Web 与 Desktop 复用 views 页面；未实跑 Electron 原生窗口。原生移动 App 没有路由配置屏，本次不新建原生设置入口；已有咨询活动展示沿用原接口。手机网页已纳入浏览器验收。

没有数据库迁移，旧客户端仍可读取旧字段；原有配置和历史评论保留。回退可 revert 本提交，但已经写入的派单/验收事件不会自动撤销。未声明仓库全套测试通过；较早全 CLI 尝试在守护进程认证夹具上失败，本次负责的路由 CLI 用例通过。
