「连接 GitHub」和「添加令牌」有什么区别

一句话：两者都是让 Multica 服务器能看到 GitHub 上的 PR。App 是 GitHub 主动通知我们，令牌是我们拿钥匙自己去查。

先分清：谁需要 GitHub 权限

智能体（你本机的 daemon）

推分支、开 PR，用的是你本机的 git / gh 登录。
这一块和下面两个按钮都没关系，现在就能正常工作（界面上显示为「仅本机 CLI」）。

Multica 服务器（ai.ferryway.cc）

要知道「这张票对应的 PR 合没合、CI 绿没绿」，关单闸门、PR 状态展示都靠它。
这两个按钮解决的就是服务器这一侧。

两条路

① GitHub App（「连接 GitHub」/「创建 GitHub App」）

  • 在 GitHub 上注册一个属于这台服务器的「应用」，再装到你的账号/组织上。
  • PR、CI 一有变化，GitHub 主动推送（webhook）给服务器，票上实时更新。
  • 可以「从 GitHub 选择」仓库，不用手敲地址。
  • 权限是只读：metadata、代码、PR、checks、状态。
  • 一次开通，整台服务器所有工作区共用；只有工作区所有者能开通。

② 令牌（「添加令牌」）

  • 你在 GitHub 生成一个个人访问令牌（PAT），贴给服务器，按范围生效（例如 github.com/jeff-kunkun）。
  • 服务器需要时自己拿令牌去问 GitHub，没有实时推送。
  • 简单，几分钟搞定，不用在 GitHub 注册应用。
  • 缺点：令牌会过期（界面显示「令牌失效」）；权限跟你个人账号绑定。
  • GitLab / Forgejo / Gitea 只有这一条路。

截图里那个灰色「连接 GitHub」

「代码仓库」区域的灰色按钮，意思是这台服务器还没有 GitHub App（鼠标移上去会提示「服务端未配置 GitHub App」）。App 建好之后它才会变亮。所以它灰着是正常的，根子在 App 没建成功。

建议：App 是长期正确的路（实时、不过期）。报错修好之前，想先让关单查得到 PR，可以临时「添加令牌」顶上；App 建好后令牌可以留着，也可以删掉。
